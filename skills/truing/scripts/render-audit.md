# Render audit: what it measures

Run it against a running server. Find the project's dev or preview command in its package scripts, start that first, and put its URL in `base`. The script probes `base` before opening a browser and exits 2 with that message when nothing answers.

The script is a floor, not a verdict. On fixtures written by people who never saw it, it finds about two thirds of seeded defects at best. A finding is a lead to confirm on the screenshot; a clean run clears only what is listed here. Weakest checks: R-VIS-036 (a tall block can still be a dull one), R-VIS-017 tiny text at narrow widths (often real, sometimes secondary lines by design), R-VIS-018 (counts hues, does not judge them), R-VIS-044 (a hint only).

The numeric thresholds quoted below (1.5x, 6 sizes, 13px/40%, 24/44px, 45%, 64px, 180px, 5 items/600ms) live in one place: the `THRESHOLDS` block at the top of `scripts/render-audit.mjs`. Change them there and quote them here, never the reverse.

The gate is geometric, not a breakpoint; `facts.rail` keeps the measured crumb |
| R-VIS-014 | largest numeric text vs h1 size, bound 1.5× | |
| R-VIS-017 | distinct computed font sizes of visible text | the source count (8) overstated the rendered count (4) |
| R-VIS-023 | document scrollWidth vs viewport, with the widest culprit | emulate a touch device at narrow widths; a desktop window at 390px gave a 2px false overflow |
| R-VIS-025 | hit-test outward from each control's centre; WCAG 2.5.8 spacing exception at 24px (the 24px circle clears every other target, and two undersized targets' centres are at least 24px apart; all rects are compared with the page scrolled to the top); controls with nothing to hit (disabled, in a disabled fieldset or under `inert`, or `pointer-events: none` with no visible child setting it back) are skipped and are not neighbours in the spacing check, whose neighbours are the same target set (tabs, checkboxes, switches and comboboxes included); `aria-disabled` alone is still a target | Radix `asChild` renames a Button's slot to `*-trigger` or `form-control`; a CSS hit-box keyed on `data-slot=button` misses them, and only hit-testing shows it |
| R-VIS-026 | text right edge vs cell content edge, numeric columns only | identifier columns (Stall No., #, ID, phone, postcode, or values of 5+ digits that start with 0 or +) are labels, not quantities; `+12`, `01` and any column whose header has the word qty/quantity/count/total/subtotal/discount/amount/size/day, singular or plural, stay quantities (whole words: "Account" is not "count", "Sunday" is not "day"). Limit: under any other header (Stock, Units, Capacity), a column of plain 1–5 digit integers or of zero-padded 5+ digit counts is read as an identifier and skipped |
| R-VIS-030 | ellipsis, line clamp, or bare nowrap clip with overflow and no title/label | |
| R-VIS-036 | blurred weight map of the content area, regions ≥75% / ≥90% of the peak, named by the component under them | regions in one card merge; app chrome and preview harness overlays are excluded (`hide` in the config) |
| R-VIS-037 | hue of the signature token; places where that hue appears | "neutral token" and "appears nowhere" are separate findings; the token is resolved to rgb first, so `color-mix()` and `oklab()` values are read; a bare-channel token is read through the wrapper its shape implies: `24 95% 53%` through `hsl()`, `37 99 235`, `220 0 50` or `0 0 255` through `rgb()`, `0.67 0.17 50` through `oklch()` (a percentage second channel is hsl; a first or second channel above 1 with no `%`, or three integers with the last above 1, is rgb; the rest is oklch, so an integer oklch such as `1 0 120` misreads as rgb, a known limit), and an unreadable one is reported as not defined, never as grey; token alpha is ignored (known limit) |
| R-VIS-000/015 | h1 and table-header computed style, majority vs outliers across pages | catches a page that missed a redesign |
| R-VIS-039 | first-line centres and block centres per row; icon box vs visible label text (sr-only labels excluded) | |
| R-VIS-009 | rows of one table carrying a solid-colour control, more than one; three or more action widths in one column; an icon-only control with no accessible name | |
| R-VIS-015 (contrast) | every visible text run against its composed ancestor background, 4.5:1 or 3:1 for large text | gradient or image backgrounds are skipped and counted in `facts.contrast.skipped`; overlays positioned outside the ancestor chain are not seen |
| R-VIS-017 (tiny text) | share of characters under 13px, bound 40% | weighted by characters, so axis ticks do not count as sentences |
| R-VIS-036 (focal block) | tallest block's share of the first viewport, floor 45%; two equal blocks side by side; `shape: form` or a dominant form is exempt | a tall block is necessary, not sufficient: still run the blur check |
| R-VIS-042 | blank band inside a card over 64px; in the first viewport, a blank band between content of at least 180px or 20% of the height, or blank space after the last block over 50% of the height | `allowVoid` for a page sparse on purpose |
| R-VIS-043 | bars on a shared baseline, in SVG (a visible `rect` (filled or outlined), or a filled `path`/`polygon` shaped like a box: outline within 12% of the box perimeter or both bottom corners filled, and a flat top) or plain elements: quantity labels present, bar width at most 64px | a date axis does not count as a scale; canvas charts are not read; not read: pill-topped bars shorter than about 0.53× their width, four-corner capsule bars shorter than about 2.6× their width, bars with an inner cutout, stroke-only `path` bars (stroke-only `rect` bars are read), horizontal bars, `<use>` bars; stepped areas whose steps stay within the top 8% still count as bars; decorative `rect` boxes (filled or outlined) of different heights on one baseline read as bars, as in v10.9, because nothing in the geometry tells them from a bar chart; only the largest shared-baseline group is checked |
| R-VIS-044 | first-viewport ink grid compared across pages; three or more nearly identical | a hint for the eye: pages with one job may share a layout |
| R-VIS-015 (labels) | five or more uppercase text elements on a page | CSS text-transform only; literal capitals are not read |
| R-VIS-023 (cards) | rows rendered as cards while the table header still shows | |
| R-VIS-030 (rows) | repeated rows with long text: height jumps 1.6× over the median, or half the rows wrap to 3+ lines | |
| R-INF-019 (raw values) | text a person can see holding whole-word `undefined`, `NaN`, `null` or `NULL`, `Invalid Date`, `[object …]`, an unfilled `{{key}}` or a replacement character (�): body text nodes, the value or shown placeholder of a text field, an input button's value, and the label a select shows. Seen means the matched characters' box survives every `overflow: hidden`/`clip` ancestor, lies on the page, and no ancestor hides it (opacity 0, visibility, display none, sr-only `clip` or `clip-path`). Text inside `code`, `pre`, `kbd`, `samp`, `textarea` or contenteditable is skipped, so a page that means to show these words puts them in `code` | Reports the first five hits; confirm each is not meant before fixing. Not read: shadow DOM, iframes, a `title` tooltip, the unselected options of a listbox (`multiple` or `size` > 1), a token split across elements, text that appears only after interaction, a bare `true`/`false`, a currency sign with no amount, plural agreement; those stay with the card's manual check |
| R-VIS-045 | a column empty in every row, or one value in every row (4+ rows) | |
| R-VIS-049 | load-time keyframe animations with delay > 0: count, and last delay + duration (5 items / 600ms) | infinite loops are excluded (R-SYN-007 / R-VIS-029); interaction-driven transitions are not measured at rest |
| R-VIS-050 | pages marked \"shell\": \"<id>\" in the config: does one page scroll while a sibling does not, and does the scroller reserve its gutter | opt-in marker; unmarked pages are never compared |
| AUDIT | HTTP errors, redirects, blank pages, a crash whose error fallback took the page, a theme that changed nothing, `expectAsset` missing | exit 2; nothing else in the report can be trusted for that render. Crash signals: the React boundary log ("The above error occurred in the <X> component" or "…in one of your React components"), which only development builds of React print, and only when `<main>` is left nearly empty (under 200 characters once its nav/header/footer/aside text is removed, and no form, table, list, input or media outside nav/header/footer/aside); on production builds set `fallbackText` (a regex; an invalid one exits 2 before any page) to the app's fallback copy, which counts only under the same emptiness test, so a page quoting it is still measured. A boundary log on a page that still rendered is `AUDIT-PARTIAL` (medium, exit 1): that area shows a fallback, the rest was measured. Limits of the emptiness test: a short, complete page with no form, table, list, input or media (a payment receipt) plus a boundary log reads as the fallback (the message gives the character count, so check the screenshot); a fallback that carries a list or form is measured as a page; nav/header/footer text is removed by first match; with no `<main>`, a sidebar built from plain `<div>`s keeps its link text and can lift a full-page fallback over 200 characters |

Not measured by any script: R-VIS-040 (product face), R-VIS-041 (finding and job), R-VIS-038 (render pair), R-VIS-046 (card tiers), R-VIS-047 (overlay weight), R-VIS-048 (motion place; R-VIS-049's load-time stagger is measured, the rest of it is not), R-SYN-013..023 (chart titles, scale ladder, insight pairing, filter placement, row-scanning cues, onboarding, undo, wayfinding, failure recovery, forms, waits), and whether the composition is any good.
